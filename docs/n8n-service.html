1. What transpired

Narration Studio was a Windows console factory: transcript → rewritten talk → N scripts → slides → MP3s → segment MP4s → merged video_{RunId}.mp4. Microsoft Agent Framework (MAF) is the inner agent runtime. This repo’s production harness still owns I/O. All PNG / MP3 / MP4 writes go through ProductionTools.

The request was to expose that factory as a service for n8n, with a custom node whose fields come from src/NarrationStudio/appsettings.json, and file browse for the transcript and stub narration (not typed Windows paths).

n8n already runs in Docker on the same PC. The container cannot see E:\…. Studio must stay a Windows process so it can use ffmpeg, SAPI, and Ollama on localhost:11434. A full video run is longer than n8n’s HTTP timeout, so the API is async (202 + jobId). Jobs run one at a time under output/jobs/{jobId}/. API keys stay off the public form.

3. Run the Windows job API

From the repo root (empty args — do not pass --orchestration):

cd E:\exercises\maf
dotnet run --project src\NarrationStudio

Or F5 the NarrationStudio launch profile. Listen URL is Service:ListenUrl (http://0.0.0.0:5088). dotnet run binds the bin copy of appsettings.json.

One process only

A second dotnet run fails with MSB3027 because NarrationStudio.exe is locked. Stop the listener on port 5088 before rebuilding.

CLI production is unchanged:

dotnet run --project src\NarrationStudio -- --orchestration direct

Service:ApiKey empty → unauthenticated API (warning in the log). Clients send X-Api-Key when set. How to mint and wire a key: §3.1.

3.1 Job API key (optional)

There is no generate-key endpoint. Mint a random string, store the same value on Studio and in the n8n credential, then restart the service. The custom node’s credentials stay optional until you set a key. /health never requires it. Other routes then need header X-Api-Key. A mismatch is 401.

1. Create a secret (PowerShell):

[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }) -as [byte[]])

A GUID is enough for local use: [guid]::NewGuid().ToString("N").

2. Put it on Studio. dotnet run binds the bin copy src/NarrationStudio/bin/Debug/net10.0-windows/appsettings.json:

"Service": {
  "ListenUrl": "http://0.0.0.0:5088",
  "ApiKey": "paste-the-secret-here"
}

Prefer not committing it. Keep source ApiKey empty and set an environment variable before dotnet run:

$env:Service__ApiKey = "paste-the-secret-here"

Stop and start Studio so the new value loads.

3. Put it on n8n. This is only n8n storing a secret and attaching it to the three Studio nodes. It is not a form field.

A Narration Studio API credential is one vault record:

Field on the credentialWhat it isWhat Studio does with it
Base URLWhere Docker n8n calls WindowsDefault http://host.docker.internal:5088 — the host’s port 5088, not localhost inside the container
API KeySame string as Service:ApiKeyHTTP header X-Api-Key on job calls. Not required for /health
ElevenLabs / OpenAI / Azure API KeyVendor keysOther headers (X-ElevenLabs-Api-Key, …). Not Service:ApiKey

Create it: n8n → Credentials → Add credential → search Narration Studio API (from the mounted custom node, not public npm). Set Base URL to http://host.docker.internal:5088. Set API Key to the exact Studio string (no extra space or quotes). Leave vendor keys blank unless you want those headers. Save. Test hits GET /health and only proves the URL is reachable, not that the job key is correct.

Attach it on all three nodes that call Studio. The sample workflow is Form → Start job → Wait until complete → Download merged video. Open each of those last three, set Credential to the record you saved, and save the workflow. If only Start job has it, Wait/Download get 401. On form submission does not get this credential.

On each request the node uses the credential Base URL (or falls back to http://host.docker.internal:5088) and, if API Key is non-empty, sends X-Api-Key. Studio compares that header to Service:ApiKey with an exact match. Empty Studio key → any request is allowed. Set Studio key + missing/wrong header → 401 { "error": "Missing or invalid X-Api-Key." }.

Do not put Service:ApiKey on the Form Trigger. That URL is shareable; the job key is a server-to-server secret (n8n encrypts credentials with N8N_ENCRYPTION_KEY). Segment count, Ollama model, voice id stay on the form.

Putting an ElevenLabs key in API Key will not unlock TTS, and will 401 the job API if it does not match Service:ApiKey. After you change the Studio key, restart dotnet run and update the n8n credential. You do not need to re-import the workflow unless a node still has no credential selected.

4. Job API

MethodPathNotes
GET/healthNo API key
POST/v1/jobsJSON or multipart. Returns 202 { jobId, status: queued }
GET/v1/jobs/{id}queued / running / complete / failed
GET/v1/jobs/{id}/eventsevents.jsonl lines
GET/v1/jobs/{id}/artifacts/mergedMP4 download

Optional create headers (never form fields): X-ElevenLabs-Api-Key, X-OpenAI-Api-Key, X-Azure-OpenAI-Api-Key.

JSON may send booleans and ints as strings ("true", "8"). undefined / null strings are ignored. Bad JSON is 400, not 500. Files may arrive as transcriptText / stubNarrationText, or as multipart names transcript, Transcript_file, stubNarration, Stub_narration_file, Dub_narration_file.

Host fallbacks: voice_transcript.txt and voice_transcript_ollama.txt at the repo root when no upload is sent.

curl http://localhost:5088/health
curl -X POST http://localhost:5088/v1/jobs -H "Content-Type: application/json" ^
  -d "{\"orchestration\":\"direct\",\"useStubNarration\":true,\"transcriptText\":\"hello\",\"stubNarrationText\":\"hello stub\"}"

5. Custom node and form

Package n8n/n8n-nodes-narration-studio is shipped as JS in dist/ (no TypeScript build). Node versions 2 and 3 share the same code. Operations: Start Job, Get Status, Wait Until Complete, Download Merged Video.

Credentials (Narration Studio API) are optional. Default base URL is http://host.docker.internal:5088. Put ElevenLabs / OpenAI / Azure keys on the credential, not the form.

Workflow n8n/workflows/narration-studio-form.json: Form Trigger → Start job → Wait until complete → Download merged video. Every field has a label and a hint with the config key. Defaults match appsettings.json. File fields cannot be pre-filled.

On the form: title, orchestration, stub flags, transcript and stub uploads, Model endpoint/model/timeout, segment/slide/talk caps, OpenAI/Azure model names, ElevenLabs voice/model ids, video size, rewrite extra instructions, keep artifacts.

Not on the form: API keys; OutputDirectory (always output/jobs/{id}).

Form Trigger names binaries after the field label (Transcript_file, Stub_narration_file). The node accepts those aliases.

6. What went wrong

  1. Public npm install — n8n’s “Install community nodes” dialog does not see this repo. Use the compose mount + local npm install in §2.
  2. “Node does not have any credentials set” — credentials were made optional.
  3. Start job 500 — n8n sent "useStubNarration": "true" (string). Studio now accepts string bools/ints and embeds file text. Parse failures return 400.
  4. MSB3027 file lock — two dotnet run instances. Stop port 5088 first.
