1. Application Overview

1.1 Purpose and core functionality

Narration Studio is a Windows console application that produces a timestamped narration video from a source transcript. It is a Microsoft Agent Framework (MAF) boilerplate: specialist agents can drive the same production tools that a deterministic runner also calls directly.

The product contract, as implemented, is:

  1. Read voice_transcript.txt (raw notes / transcript).
  2. Rewrite it into a spoken ~7-minute talk, saved as output/scripts/narration-rewritten.txt. Today this rewrite is usually stubbed from voice_transcript_ollama.txt when Studio:UseStubNarration is true; otherwise it calls local Ollama.
  3. Split that rewritten talk into exactly 8 narration scripts.
  4. Plan at most 5 on-screen phrases per script and render them as PNG slides.
  5. Synthesize audio-01.mp3 … audio-08.mp3 via ElevenLabs (if an API key is configured) or Windows SAPI + ffmpeg.
  6. Sync each MP3 with that segment’s slides into video-01.mp4 … video-08.mp4.
  7. Merge into video_yyyyMMdd_HHmmss.mp4 in the output folder.

The application is not a web service, desktop GUI, or multi-user system. There is no ASP.NET host, no HTTP listener, no SPA, and no SQL database. A developer expecting MVC / REST layers will not find them; the analogue of “controllers” is ProductionApp plus tool methods on ProductionTools.

Composition is Generic Host (Host.CreateApplicationBuilder in Program.cs). Every collaboration object is a singleton. Control flows top-down: host → ProductionApp.RunAsync → either WorkflowHost (agents) or DirectPipelineRunner → ProductionTools → domain services → disk and external processes/APIs.

1.4 Overall data and control flow

Data is a single in-memory PipelineState cloned on read via JSON round-trip, persisted after every mutation to output/pipeline-state.json. Artifacts are files. There is no message bus.

Control flow for a typical current run (UseStubNarration=true, --orchestration direct):

  1. Program.cs builds the host and calls ProductionApp.RunAsync(args).
  2. Mutex acquired. Transcript and output directory resolved. PipelineStore.Initialize deletes previous generated files.
  3. Because stubbing is on, RephraseTranscriptIntoNarration copies the stub file into narration-rewritten.txt and sets NarrationPath.
  4. Direct mode always re-segments, re-plans, re-renders, re-synthesizes, re-composes, and merges.
  5. Console prints Done: {merged path}.

Status strings written onto state: created → narration-ready → scripts-ready → slides-planned → slides-rendered → audio-ready → videos-ready → complete.

2.3 How the layers communicate

All communication is in-process method calls through constructor-injected singletons. Agents do not get a private copy of services; they receive AIFunction wrappers around the same ProductionTools instance. That is why a tool called by an agent updates the same PipelineStore that DirectPipelineRunner later reads.

External communication:

  • Ollama — HTTP via OllamaApiClient (OllamaSharp) at Model:Endpoint, default http://localhost:11434.
  • ElevenLabs — HTTP POST https://api.elevenlabs.io/v1/text-to-speech/{voiceId} with header xi-api-key.
  • ffmpeg / ffprobe — child processes, stdout/stderr captured asynchronously to avoid deadlock, 8-minute timeout.
  • Windows SAPI — System.Speech.Synthesis.SpeechSynthesizer writing WAV, then ffmpeg to MP3.

2.4 Why this shape

  • Tools as the real pipeline. Agents are optional drivers. Direct mode exists so production still works when the LLM is slow, missing, or poorly follows handoff instructions. Confirmed in ProductionApp: agent failure to produce a merged file always falls through to DirectPipelineRunner.
  • Wipe outputs on start. Earlier versions skipped existing PNGs/MP3s/MP4s, so a new narration could be muxed with old media. Initialize now deletes generated trees.
  • Stub rewrite. Local Ollama rewrite is long-running (timeout 30 minutes). Stubbing lets the rest of the factory be developed against a known talk.
  • Windows TFM. net10.0-windows is required for System.Speech.

3. Detailed Component Breakdown

This section covers every significant type in the project. Small helpers are included because they affect production reliability.

3.1 Program.cs — composition root

Purpose. Create Generic Host, bind options, register singletons, run the app. There is no Main class; top-level statements are used.

Config loading (confirmed, and easy to get wrong). Host.CreateApplicationBuilder uses the process current directory as content root. Launch profile workingDirectory is the repo root ($(ProjectDir)..\..), so the first appsettings.json lookup is {cwd}/appsettings.json, which does not exist. The second explicit call loads AppContext.BaseDirectory/appsettings.json — the copy MSBuild places next to the DLL. That is the file that actually configures a dotnet run from the repo root.

Inputs / outputs. Input: args, JSON files, environment variables (Host default providers). Output: constructed IServiceProvider, then ProductionApp.RunAsync.

Error handling. None locally; failures bubble from RunAsync and crash the process (non-zero exit). Confirmed: no try/catch in Program.cs.

3.2 ProductionApp

File: src/NarrationStudio/ProductionApp.cs

Responsibilities. Exclusive run (mutex), resolve transcript/output/orchestration, initialize store (which wipes artifacts), print a banner (including TTS provider), optionally apply stub rewrite before agents exist, choose direct vs agent workflow, failover to direct if merge is missing, print Done.

Important methods.

MethodBehavior
RunAsync(string[] args)Full run lifecycle described in §4.
ResolveTranscriptPathCandidates: first non--- arg, then Studio:TranscriptPath, then several relative voice_transcript.txt locations. First existing file wins. Else FileNotFoundException.
ResolveOutputDirectoryStudio:OutputDirectory or output, rooted against current directory.
ResolveOrchestration--orchestration=x or --orchestration x. Default handoff.

Design decision — stub before TryCreate. Creating agents calls OllamaChatClientFactory.Create and logs Ollama immediately. If stub rewrite waited until a rewriter tool ran, users saw Ollama connecting and assumed the stub was ignored. Stub copy now happens first.

Auth. None. Process identity is the logged-in Windows user.

3.3 PipelineStore and PipelineState

Files: Services/PipelineStore.cs, Models/PipelineModels.cs

Purpose. Single source of pipeline truth for one process run. Analogous to a unit-of-work + repository, but for files.

Internal structure. Private PipelineState _state plus object _gate. Snapshot() serializes then deserializes with source-generated PipelineJsonContext so callers cannot mutate live state without Mutate. Every Mutate writes output/pipeline-state.json.

Initialize. Sets transcript and output paths, creates directories, deletes previous scripts/slides/audio/video, agent-file-memory, leftover video_*.mp4, and old state JSON, then persists a fresh state. Returns the count of deleted files for the banner.

Naming helpers (confirmed).

audio-{nn}.mp3
video-{nn}.mp4
segment-{nn}-slide-{nn}.png
narration-rewritten.txt
video_{RunId}.mp4   where RunId = yyyyMMdd_HHmmss at store construction

State fields. See §5. RunId is assigned in the constructor before Initialize; wiping old merged videos uses glob video_*.mp4, not the new RunId.

SummarizeForAgent. Counts scripts/slides/images/audio/videos from in-memory segments plus File.Exists. “Next required step” is a priority chain. After wipe, in-memory segments are empty even if a human dropped files on disk mid-run — agents are steered by this summary, not by scanning leftover files (except existence checks on paths already recorded in state).

Concurrency. Lock around snapshot/mutate/initialize. Tool methods sometimes snapshot, work, then mutate — a second thread could interleave, but the app is effectively single-threaded aside from ffmpeg async reads.

Why JSON clone for Snapshot. Cheap isolation without implementing ICloneable on a graph of lists. Cost is negligible at this scale.

3.5 NarrationRewriteService and OllamaChatClientFactory

File: Services/NarrationRewriteService.cs (both types)

OllamaChatClientFactory. Lazy singleton IChatClient (OllamaApiClient) with a .NET Lock. HttpClient BaseAddress = endpoint, Timeout = max(1, TimeoutMinutes) minutes. Used both for rewrite and, when no Azure/OpenAI key, for agent orchestration.

RephraseAsync.

  • If UseStubNarration: resolve stub path (transcript dir, cwd, BaseDirectory, and a walk-up from bin). Strip <think> and fences. Reject if length < 400 characters. Does not send the raw transcript to a model.
  • Else: system prompt asks for ~TargetTalkMinutes * 140 words, spoken voice, no invented facts. User message is the raw transcript. Temperature 0.35. Same length check on the result.

Why 400 characters. Heuristic to catch empty or “thinking only” model output. Not a linguistic quality gate.

3.6 TranscriptSegmenter

Splits on (?<=[\.!\?])\s+, then packs sentences into SegmentCount buckets by character budget. If too few groups, it peels sentences from the richest bucket. Titles are “Segment NN — {first sentence truncated to 72 chars}”.

WriteScriptFiles overwrites narration-{nn}.txt and concatenates narration-all.txt.

Edge case (confirmed). If every remaining group has a single sentence and count is still below 8, the loop can break after duplicating one sentence into a new group, then Take(buckets) may still return fewer than 8. SegmentTranscriptIntoEightScripts would then throw. Unlikely for a 7-minute talk; possible for a tiny stub.

3.7 SlidePlannerService

Clamps max slides to 1..5. Sentence-splits the script; if more sentences than max, concatenates chunks. Phrases truncated to 220 characters with ellipsis. Returns List<SlideSpec> with numbers and phrases; ImagePath filled later by render.

This is deterministic NLP-by-regex, not an LLM. The slide_planner agent is instructed to call this tool rather than invent phrases, though a misbehaving model could still skip the tool (handoff risk). Direct mode always calls the tool.

3.8 SlideImageRenderer

ImageSharp PNG, 1920×1080 by default. Dark navy canvas, gold rule, header “SEGMENT nn · SLIDE x/y”, wrapped body text, footer = segment title. Fonts tried: Segoe UI, Arial, Calibri, else first system family.

WriteAllBytesWithRetry. FileMode.Create with share ReadWrite|Delete, 6 attempts, then write a GUID sidecar and copy over. Exists because Windows file locks from ImageSharp, explorers, or leftover ffmpeg were observed during development.

3.9 TtsService and FfmpegProcess

Key resolution. Studio:ElevenLabsApiKey first, else env ELEVENLABS_API_KEY. If present: POST MPEG to ElevenLabs; on non-success throw with status and body (no fallback to SAPI). If absent: SAPI WAV, or NAudio sine “tone bed” if SAPI throws, then ffmpeg libmp3lame.

DescribeProvider is used in the startup banner so operators can see ElevenLabs vs SAPI without reading logs.

FfmpegProcess. Starts ffmpeg/ffprobe with redirected stdout and stderr both read asynchronously, WaitForExit 8 minutes, kill process tree on timeout. This avoids the classic deadlock of reading one stream to end before the other. Probe returns stdout; run returns stderr (unused except on failure).

Duration. ffprobe format duration; parse fail defaults to 5 seconds (would distort slide timing if probe fails).

3.10 VideoComposerService

ComposeSegment. Writes ffmpeg concat demuxer list: each slide file + duration = max(0.4, audioDuration / slideCount), last file repeated (ffmpeg concat still-image requirement). Mixes concat video with the MP3, scale/pad to configured size, fps, libx264 stillimage, aac, -shortest, faststart. -y overwrites.

Merge. Concat list of the eight MP4s. Tries stream copy first; on any exception re-encodes libx264+aac. That fallback is why mismatched timebases from vfr concat can still produce a playable master.

Path escaping for concat files: backslash → slash, single quote → ffmpeg concat escape.

3.11 DirectPipelineRunner

Logs, prints status, rephrases only if NarrationPath is empty/missing (so ProductionApp’s stub is not duplicated unless something deleted the file), then always segments, plans, renders, synthesizes, composes, merges. No skip-if-exists on media. Return value is the merge tool’s string; ProductionApp also reads MergedVideoPath from state.

3.12 AgentFactory and ProductionCrew

ProductionCrew is a record of seven AIAgent instances.

TryCreate. Builds one IChatClient: Azure OpenAI if endpoint set (key or DefaultAzureCredential), else OpenAI if OPENAI_API_KEY, else Ollama. Failure returns false → ProductionApp uses direct mode.

Each agent: chatClient.AsAIAgent(ChatClientAgentOptions) with id/name/description, instructions, tools, and two context providers. Then .AsBuilder().Use(guardrails.RunAsync).Use(guardrails.FunctionAsync).Build().

File memory: MAF FileMemoryProvider + FileSystemAgentFileStore under output/agent-file-memory, working folder production-notes. Inferred: the package persists agent notes as files; this repo does not reimplement that store. Initialize deletes that directory each run, so memory does not survive reruns.

Chat client priority is Azure → OpenAI → Ollama. A developer with Azure env vars set will not use local Ollama for specialists even if Ollama is running. Confirmed in CreateChatClient.

3.13 WorkflowHost

Handoff. AgentWorkflowBuilder.CreateHandoffBuilderWith(coordinator). If stubbing, rewriter is omitted from the graph. Specialists hand back to coordinator. Coordinator has autonomous mode, turnLimit 8, continuation prompt to GetPipelineStatus. Inferred: MAF runtime interprets handoff conditions as natural-language routing hints to the model, not compiled predicates.

Sequential. BuildSequential with rewriter omitted when stubbing.

RunAsync. InProcessExecution.RunStreamingAsync, sends TurnToken(emitEvents: true), prints AgentResponseUpdateEvent text grouped by executor id, returns on WorkflowOutputEvent.

BuildUserPrompt. Injects stub vs Ollama rewrite step plus live SummarizeForAgent.

3.14 ProductionGuardrails

Inbound user messages containing blocked terms (harmful, illegal, violence, exploit, malware, bypass paywall) are replaced with a blocked marker; the run short-circuits with a refusal. All messages get email and ###-###-#### phone redaction.

FunctionAsync logs tool start/finish. It counts the word “slide” in string results of tools whose names contain “Slide” and logs a warning if count exceeds max slides × segments. Confirmed: it does not trim or reject the result. The 8-script cap is enforced in tools by throwing, not here.

Guardrails apply only to agent runs, not DirectPipelineRunner.

3.15 ProductionContextProvider

On invoke, injects instructions: current summary, exact file naming, segment/slide caps, stay on task. After invoke, appends truncated assistant text to PipelineState.Notes (max 24, drop oldest). Notes are persisted in pipeline-state.json.

3.16 Configuration types

StudioOptions section Studio; OllamaOptions section Model. Defaults in the class match appsettings for segment counts, stubbing, voice id, video size. Options are captured at construction (IOptions<T>.Value), so reloadOnChange on JSON files does not update live option objects already injected. Confirmed: services store _options = options.Value.

3.17 Launch profile

Properties/launchSettings.json profile NarrationStudio: empty args, working directory repo root. That is why transcripts at repo root are found and output is E:\exercises\maf\output rather than under bin.

4. Request/Response and Execution Flows

There are no inbound HTTP requests. “Request” here means a developer invoking the executable.

4.1 Direct orchestration (confirmed current happy path)

  → Bind Studio + Model options
  → ProductionApp.RunAsync
      → Mutex NarrationStudio.Production

      → UseStubNarration → ProductionTools.RephraseTranscriptIntoNarration

      → Console: Done: output\video_{RunId}.mp4

4.2 Handoff orchestration

  1. Same init and optional stub rewrite.
  2. AgentFactory.TryCreate — if this throws/returns false, jump to direct.
  3. CreateHandoffWorkflow then RunAsync with user prompt and ApplicationStopping.
  4. Coordinator should call GetPipelineStatus and hand off. Specialists call tools that mutate store and disk.
  5. Autonomous continuation up to 8 coordinator turns (inferred MAF semantics).
  6. If MergedVideoPath missing or file absent → warning log → DirectPipelineRunner. Direct will not skip media generation, so a partial agent run is overwritten into a complete video (scripts already in memory if agents segmented; if not, direct segments from rewritten file).

Subtlety. Direct after a partial agent run still requires in-memory Segments or it will call SegmentTranscriptIntoEightScripts from the rewritten file. Agent-authored scripts in memory are kept for that process; they are not reloaded from disk on a new process because Initialize wipes and does not hydrate from leftover JSON (JSON was also deleted).

4.3 Sequential orchestration

Same as handoff but BuildSequential runs specialists in a fixed list. Stubbing removes the rewriter from that list because ProductionApp already wrote the talk.

4.5 Ollama rewrite request (when stubbing off)

Via Microsoft.Extensions.AI GetResponseAsync on OllamaApiClient. Inferred wire format: OllamaSharp talks to Ollama’s HTTP API (typically /api/chat). This repo does not construct that JSON manually. Timeout is the HttpClient timeout (default 30 minutes).

4.6 Frontend-to-backend-to-database

Does not apply. Console is the UI; services are in-process; “database” is pipeline-state.json written on Mutate.

There is no database server, ORM, or migration framework. Documented here is the file data layer that plays the same role.

5.4 Schema (important fields)

5.5 Queries and access

No query language. Access is LINQ over in-memory lists inside locked Mutate/Snapshot. There is no index. Hydration from a previous JSON file is not implemented; Initialize always starts empty segments after wipe.

5.6 Validation and integrity

  • Segment count must equal Studio:SegmentCount (default 8) at segment and merge boundaries.
  • Slide lists trimmed to MaxSlidesPerSegment at render time.
  • Stub/Ollama narration must be ≥ 400 characters.
  • JSON save of agent scripts uses PipelineJsonContext.ListNarrationSegment.
  • No checksums, no transactional disk writes (JSON write is not atomic replace; a crash mid-write can corrupt pipeline-state.json). Next run deletes it anyway.

5.7 Caching

Ollama client instance is cached for process lifetime. No artifact cache: reruns recompute everything. ImageSharp fonts are loaded per render call (minor cost).

7. Frontend / Internal UI Workings

There is no component hierarchy, router, form library, or rendering lifecycle in the SPA sense.

7.1 Console as UI

  • Banner in ProductionApp: transcript, output, mode, cleared file count, stub line, TTS provider.
  • Tool progress in DirectPipelineRunner: each tool return string WriteLine.
  • Agent stream in WorkflowHost: executor id headers and incremental update.Update.Text.
  • Host logging Microsoft.Extensions.Logging to console (default Host logging).

7.2 State management

UI is stateless. PipelineStore is the application state. Operators infer progress from logs and from files appearing under output/.

7.3 Event handling

Ctrl+C triggers Host ApplicationStopping, which WorkflowHost passes into MAF streaming. Direct ffmpeg/TTS does not observe that token (limitation). Mutex is released when the process exits (using Dispose on Mutex).

7.4 Validation

No forms. Invalid CLI transcript path → FileNotFoundException before work starts.

9. Security

9.1 Authentication and authorization

No user login, roles, or tokens for using Narration Studio. Anyone who can run the EXE as the current user can produce videos and read output/.

Outbound: ElevenLabs API key; optional OpenAI key; optional Azure key or DefaultAzureCredential (managed identity / VS / az cli — inferred Azure.Identity behavior).

9.2 Data protection

Transcripts and generated media sit unencrypted on disk under output/ (gitignored). Notes in pipeline-state.json may contain agent excerpts. PII redaction in guardrails is regex-only on agent messages, not on transcript files or TTS payloads. Emails in the source talk are sent to ElevenLabs in full. Confirmed: redaction does not wrap ProductionTools in direct mode.

9.3 Input validation

Filesystem paths are combined from config and args without a sandbox. A transcript argument of an unexpected file will be read if it exists. ffmpeg concat lists include absolute paths. There is no command-injection via ArgumentList (good: ProcessStartInfo.ArgumentList is used, not a single shell string).

9.4 Session / tokens

No app sessions. Named mutex is a lock, not auth. HttpClients do not implement retry/auth refresh.

10. Error Handling and Edge Cases

10.1 Propagation

Exceptions from services → tools → DirectPipelineRunner or MAF tool invocation → ProductionApp catch logs Error and rethrows. No global exception handler / EventId taxonomy beyond default logger categories.

10.2 Logging

ILogger on ProductionApp, DirectPipelineRunner, AgentFactory, WorkflowHost, NarrationRewriteService, TtsService, ProductionGuardrails. Information for provider selection and ElevenLabs writes; Warning for stub rewrite, SAPI failure, agent create failure, incomplete agent merge, guardrail block; Error for pipeline failure.

No structured file log, no Application Insights, no correlation ID beyond RunId in state/filenames.

10.3 Retries

OperationRetry
Delete generated filesUp to 8 attempts, backoff 150ms × attempt
PNG write6 attempts + sidecar copy
ffmpeg mergeOne fallback re-encode, not a counted retry
ElevenLabs / Ollama HTTPNone

10.4 Failure scenarios

  • Second instance: InvalidOperationException mutex.
  • Missing transcript / stub: FileNotFoundException.
  • Stub too short: InvalidOperationException.
  • Player has video_*.mp4 open: Initialize throws IOException after retries.
  • ffmpeg missing: Win32Exception / “failed to start ffmpeg”.
  • ElevenLabs 401/quota: InvalidOperationException with body; run aborts mid-audio (earlier MP3s already written this run; next run wipes them).
  • Ollama down in handoff: TryCreate may still construct a client; failure appears when the first model call happens. Direct mode with stubbing never needs Ollama.
  • Agent never merges: failover DirectPipelineRunner.

10.5 Validation failures

Wrong agent JSON for SaveNarrationScripts, empty transcript, missing audio before compose. All throw; no partial merge if fewer than SegmentCount videos.

13. Performance and Scalability

StageCostNotes
Stub rewriteNegligibleFile copy + strip
Ollama rewriteMinutes; up to 30 min timeoutSingle request; temperature 0.35
Segment / planMillisecondsRegex
PNG renderSeconds for ~40 imagesSequential CPU; ImageSharp
ElevenLabs TTSDominant when enabled8 sequential HTTP calls, 3 min timeout each worst case
ffmpeg composeHigh CPU8 sequential encodes 1920×1080
ffmpeg merge copyFastRe-encode fallback is slow

Concurrency. No parallel TTS or ffmpeg. Could be added but would contend on API rate limits and disk. Mutex forbids two pipelines.

Scalability. Designed for one talk, one machine, one run. Not multi-tenant. Bottleneck for “correct sounding” video is ElevenLabs quota/latency; bottleneck for local-only is SAPI + ffmpeg.

Caching. Intentionally disabled for media so reruns match current narration.

15.3 Extending

  • Ninth segment: raise SegmentCount; verify ffmpeg merge and agent instructions (several prompts hardcode “8”).
  • New specialist: add tool method, wrap in AgentFactory, add handoff edges, update sequential list and coordinator text.
  • Cloud LLM rewrite: swap OllamaChatClientFactory usage in NarrationRewriteService; keep stub flag.

15.5 Pitfalls and technical debt

  • appsettings loaded from bin copy; editing source JSON requires rebuild/copy.
  • Secrets in tracked JSON.
  • Agent prompts still mention “8” and audio-01..08 even if SegmentCount changes.
  • Guardrail slide counter does not enforce.
  • CancellationToken.None on TTS/rewrite.
  • SummarizeForAgent next-step order prefers audio before remaining slide plans if scripts exist — odd if someone called TTS without planning (direct mode does not do that).
  • No tests.
  • Tone-bed fallback can produce a video that “works” with a beep instead of speech if SAPI fails and no ElevenLabs key.
  • FileMemoryProvider types come from MAF; upgrading Microsoft.Agents.AI can break AgentFactory.

18.5 Known limitations

  • No GUI, API server, DB, tests, CI, or multi-run resume.

  • Hardcoded “eight” in several prompts.
  • Secrets currently live in appsettings.json.
  • No max transcript size; ElevenLabs character limits can fail a segment.
  • Slide timing is even split of audio duration, not word-level alignment.
  • Guardrails do not apply to direct mode and do not enforce slide counts.
