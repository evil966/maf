1. Application Overview

1.1 Purpose and core functionality

Narration Studio is a Windows console application that produces a timestamped narration video from a source transcript. It is a Microsoft Agent Framework (MAF) boilerplate with a harness-centric loop: ProductionHarness owns run policy (stub copy, MAF or direct execution, failover, artifact checks). Specialist agents can drive the same production tools that DirectExecutor also calls. Agents do not own I/O; tools do.

The product contract, as implemented, is:

  1. Read voice_transcript.txt (raw notes / transcript).
  2. Rewrite it into a spoken ~7-minute talk, saved as output/scripts/narration-rewritten.txt. Today this rewrite is usually stubbed from voice_transcript_ollama.txt when Studio:UseStubNarration is true; otherwise it calls local Ollama.
  3. Split that rewritten talk into Studio:SegmentCount narration scripts (default 8).
  4. Plan at most Studio:MaxSlidesPerSegment excerpts per script (default 5). By default Ollama rewrites each excerpt into one sentence unless Studio:UseStubSlidePhrases is true. That sentence is drawn on the PNG. The original excerpt is kept as SourcePhrase.
  5. Synthesize audio-01.mp3 … audio-NN.mp3 via ElevenLabs (if an API key is configured) or Windows SAPI + ffmpeg.
  6. Sync each MP3 with that segment’s slides into video-01.mp4 … video-NN.mp4.
  7. Merge into video_yyyyMMdd_HHmmss.mp4 in the output folder.

The application is still a Windows console factory, not a multi-user SPA or SQL product. With empty args (or --service) the same EXE also hosts a small Kestrel API on http://0.0.0.0:5088 so Docker n8n can drive productions stage by stage. Passing --orchestration or a transcript path still runs the CLI and exits. There is no MVC site. The analogue of “controllers” is JobEndpoints (HTTP) plus the thin ProductionApp CLI; ProductionHarness still owns CLI / compatibility-job policy; ProductionTools is still the only PNG/MP3/MP4 surface. See §19.

1.4 Overall data and control flow

Data is a single in-memory PipelineState cloned on read via JSON round-trip, persisted after every mutation to output/pipeline-state.json. Artifacts are files. There is no message bus.

Control flow for a typical current run (UseStubNarration=true, --orchestration direct):

  1. Program.cs treats --orchestration / a transcript path as CLI and calls ProductionApp.RunAsync(args). Empty args start the job API instead (§19).
  2. Mutex acquired. Transcript and output directory resolved. PipelineStore.Initialize deletes previous media (scripts/slides/audio/video and video_*.mp4) but keeps prior output/agent-file-memory/production-notes-* folders. It creates a new timestamped memory folder and writes run.txt.
  3. Banner includes Harness : MAF+tools, TTS provider, optional stub lines, and Memory : {full path}.
  4. ProductionHarness.RunAsync copies stub narration if configured, then runs DirectExecutor (or MAF, with failover to direct if TryCreate fails or merge is missing). Host ApplicationStopping is passed through.
  5. Direct mode always re-segments, plans slides (Ollama sentences unless UseStubSlidePhrases), re-renders PNGs, re-synthesizes, re-composes, and merges. Each tool call appends events.jsonl. Each Mutate refreshes pipeline-status.txt and notes.txt.
  6. HarnessChecks.Verify requires status == complete, expected script count, slides ≤ max, audio/video files, and a merged path on disk. Failure throws HarnessCheckException (non-zero exit) even if an agent said Done.
  7. Console prints Done: {merged path}.

Status strings written onto state: created → narration-ready → scripts-ready → slides-planned → slides-rendered → audio-ready → videos-ready → complete.

2.3 How the layers communicate

All communication is in-process method calls through constructor-injected singletons. Agents do not get a private copy of services; they receive AIFunction wrappers around the same ProductionTools instance. That is why a tool called by an agent updates the same PipelineStore that DirectExecutor later reads.

External communication:

  • Ollama — HTTP via OllamaApiClient (OllamaSharp) at Model:Endpoint, default http://localhost:11434.
  • ElevenLabs — HTTP POST https://api.elevenlabs.io/v1/text-to-speech/{voiceId} with header xi-api-key.
  • ffmpeg / ffprobe — child processes, stdout/stderr captured asynchronously to avoid deadlock, 8-minute timeout.
  • Windows SAPI — System.Speech.Synthesis.SpeechSynthesizer writing WAV, then ffmpeg to MP3.

2.4 Why this shape

  • Harness owns the loop. Agents are optional drivers. Direct mode exists so production still works when the LLM is slow, missing, or poorly follows handoff instructions. Confirmed in ProductionHarness: direct mode, failed TryCreate, or a missing merged file always falls through to DirectExecutor. After tools finish, HarnessChecks can still fail the process.
  • Wipe media on start; keep memory folders. Scripts, slides, audio, video, and leftover video_*.mp4 are deleted so a rerun cannot stitch old media. Agent memory is not deleted: each run uses output/agent-file-memory/production-notes-{RunId}/.
  • Stub rewrite. Local Ollama rewrite is long-running (timeout 30 minutes). Stubbing lets the rest of the factory be developed against a known talk.
  • Windows TFM. net10.0-windows is required for System.Speech.

3. Detailed Component Breakdown

This section covers every significant type in the project. Small helpers are included because they affect production reliability.

3.1 Program.cs — composition root

Purpose. Choose CLI vs job service, bind options, register the pipeline, run. There is no Main class; top-level statements are used.

CLI vs service (confirmed). IsProductionCli is true if args contain --cli, --orchestration, or a non-flag token (transcript path). Then Generic Host runs ProductionApp and exits. --service forces the web host. Empty args start Kestrel on Service:ListenUrl (default http://0.0.0.0:5088), register JobStore / JobQueue / JobWorker, and map JobEndpoints.

Config loading (confirmed, and easy to get wrong). Launch profile workingDirectory is the repo root ($(ProjectDir)..\..), so the first appsettings.json lookup is {cwd}/appsettings.json, which does not exist. The second explicit call loads AppContext.BaseDirectory/appsettings.json — the copy MSBuild places next to the DLL. That is the file that actually configures a dotnet run from the repo root.

Inputs / outputs. Input: args, JSON files, environment variables. CLI output: ProductionApp.RunAsync. Service output: HTTP on 5088 until Ctrl+C.

Pipeline registrations live in Hosting/StudioServiceCollection.AddNarrationStudioPipeline. Runtime options, tools, harness, agents, and ProductionApp are scoped so each job can overlay Studio: / Model:. A few pure helpers stay singleton (segmenter, slide planner, PNG renderer, video composer).

Error handling. CLI failures bubble from RunAsync and crash the process. Service JSON parse errors return 400; job failures are stored on the job record.

3.2 ProductionApp

Responsibilities. Thin CLI: exclusive run (mutex), resolve transcript/output/orchestration, initialize store (wipes media, creates timestamped memory folder), print a banner (including Harness : MAF+tools, TTS provider, stub flags, Memory path), write run.txt, call ProductionHarness.RunAsync, print Done. It does not choose MAF vs direct, copy the stub, or verify artifacts — those live on the harness.

3.2b ProductionHarness

File: src/NarrationStudio/Harness/ProductionHarness.cs

Purpose. The run loop. Confirmed sequence:

  1. If UseStubNarration, call RephraseTranscriptIntoNarration before AgentFactory.TryCreate, so stubbing does not look like an Ollama rewrite.
  2. If orchestration is direct, or TryCreate fails, run DirectExecutor.RunAsync(ApplicationStopping).
  3. Else build sequential or handoff workflow, run it with the same cancellation token, then if MergedVideoPath is empty or the file is missing, log a warning and run DirectExecutor.
  4. Always call HarnessChecks.Verify(). A successful-looking agent transcript still fails the process if artifacts are wrong.

Handoff and sequential are MAF. Direct, CLI, failover, and this class are this app.

3.2c HarnessEvents and HarnessChecks

HarnessEvents (Harness/HarnessEvents.cs) appends one JSON line per tool to output/agent-file-memory/production-notes-{RunId}/events.jsonl: timestamp, name, elapsedMs, ok, error. Tools wrap work in Trace / TraceAsync. If output is not initialized yet, writes are skipped.

HarnessChecks (Harness/HarnessChecks.cs) is a static-capable verifier used after the run and in unit tests. Failures throw HarnessCheckException listing:

  • status is not complete
  • segment count ≠ Studio:SegmentCount
  • any segment has more slides than MaxSlidesPerSegment
  • audio or video path missing or file absent
  • merged video path missing or file absent

This is the process-level Done gate. Agents cannot skip it.

3.3 PipelineStore and PipelineState

Files: Services/PipelineStore.cs, Models/PipelineModels.cs

Purpose. Single source of pipeline truth for one process run. Analogous to a unit-of-work + repository, but for files.

Internal structure. Private PipelineState _state plus object _gate. Snapshot() serializes then deserializes with source-generated PipelineJsonContext so callers cannot mutate live state without Mutate. Every Mutate writes output/pipeline-state.json.

Initialize. Sets transcript and output paths, creates directories, deletes previous scripts/slides/audio/video, leftover video_*.mp4, and old pipeline-state.json. It does not delete agent-file-memory. It creates AgentMemoryDirectory = output/agent-file-memory/production-notes-{RunId} and writes snapshots there on every persist. Returns the count of deleted media files for the banner.

Naming helpers (confirmed).

audio-{nn}.mp3
video-{nn}.mp4
segment-{nn}-slide-{nn}.png
narration-rewritten.txt
video_{RunId}.mp4   where RunId = yyyyMMdd_HHmmss at store construction
production-notes-{RunId}\   under output\agent-file-memory\

State fields. See §5. RunId is assigned in the constructor before Initialize; wiping old merged videos uses glob video_*.mp4, not the new RunId.

SummarizeForAgent. Counts scripts/slides/images/audio/videos from in-memory segments plus File.Exists. “Next required step” is a priority chain. After wipe, in-memory segments are empty even if a human dropped files on disk mid-run — agents are steered by this summary, not by scanning leftover files (except existence checks on paths already recorded in state).

Concurrency. Lock around snapshot/mutate/initialize. Tool methods sometimes snapshot, work, then mutate — a second thread could interleave, but the app is effectively single-threaded aside from ffmpeg async reads.

Why JSON clone for Snapshot. Cheap isolation without implementing ICloneable on a graph of lists. Cost is negligible at this scale.

3.5 NarrationRewriteService and OllamaChatClientFactory

File: Services/NarrationRewriteService.cs (both types)

OllamaChatClientFactory. Lazy singleton IChatClient (OllamaApiClient) with a .NET Lock. HttpClient BaseAddress = endpoint, Timeout = max(1, TimeoutMinutes) minutes. Used both for rewrite and, when no Azure/OpenAI key, for agent orchestration.

RephraseAsync.

  • If UseStubNarration: resolve stub path (transcript dir, cwd, BaseDirectory, and a walk-up from bin). Strip <think> and fences. Reject if length < 400 characters. Does not send the raw transcript to a model.
  • Else: system prompt asks for ~TargetTalkMinutes * 140 words, spoken voice, no invented facts. User message is the raw transcript. Temperature 0.35. Same length check on the result. Logs elapsed seconds: Received rewritten narration (N words) in Xs.

Why 400 characters. Heuristic to catch empty or “thinking only” model output. Not a linguistic quality gate.

3.6 TranscriptSegmenter

Splits on (?<=[\.!\?])\s+, then packs sentences into SegmentCount buckets by character budget. If too few groups, it peels sentences from the richest bucket. Titles are “Segment NN — {first sentence truncated to 72 chars}”.

WriteScriptFiles overwrites narration-{nn}.txt and concatenates narration-all.txt.

Edge case (confirmed). If every remaining group has a single sentence and count is still below 8, the loop can break after duplicating one sentence into a new group, then Take(buckets) may still return fewer than 8. SegmentTranscriptIntoEightScripts would then throw. Unlikely for a 7-minute talk; possible for a tiny stub.

3.7 SlidePlannerService and SlidePhraseRewriteService

SlidePlannerService clamps max slides to 1..5. Sentence-splits the script; if more sentences than max, concatenates chunks. Each item gets SourcePhrase and an initial Phrase (trimmed to 220 characters). ImagePath is filled later by render. This split is deterministic regex, not an LLM.

SlidePhraseRewriteService (Services/SlidePhraseRewriteService.cs) then, for every slide that is not yet PhraseRewritten:

  • If UseStubSlidePhrases: copy SourcePhrase into Phrase (no HTTP). Independent of UseStubNarration.
  • Else: call local Ollama. The model must return exactly one short sentence (about 8–22 words). Thinking tags and fences are stripped via NarrationRewriteService.StripModelExtras. Temperature 0.2. Empty Ollama output falls back to the source excerpt with a warning.

The sentence is stored in Phrase; the PNG renderer draws Phrase only. Live Ollama rewrites log Rephrased slide NN-MM in Xs: … and a batch total. Stub slides do not need Ollama.

PlanSlidesForAllSegments and RenderAllSlideImages are both async and both call RewriteAllAsync. Render skips slides already marked rewritten so the same excerpt is not billed twice in one run.

3.8 SlideImageRenderer

ImageSharp PNG, 1920×1080 by default. Dark navy canvas, gold rule, header “SEGMENT nn · SLIDE x/y”, wrapped body text, footer = segment title. Fonts tried: Segoe UI, Arial, Calibri, else first system family.

WriteAllBytesWithRetry. FileMode.Create with share ReadWrite|Delete, 6 attempts, then write a GUID sidecar and copy over. Exists because Windows file locks from ImageSharp, explorers, or leftover ffmpeg were observed during development.

3.9 TtsService and FfmpegProcess

Key resolution. Studio:ElevenLabsApiKey first, else env ELEVENLABS_API_KEY. If present: POST MPEG to ElevenLabs; on non-success throw with status and body (no fallback to SAPI). If absent: SAPI WAV, or NAudio sine “tone bed” if SAPI throws, then ffmpeg libmp3lame.

DescribeProvider is used in the startup banner so operators can see ElevenLabs vs SAPI without reading logs.

FfmpegProcess. Starts ffmpeg/ffprobe with redirected stdout and stderr both read asynchronously, WaitForExit loop with 8-minute deadline, kill process tree on timeout or CancellationToken. This avoids the classic deadlock of reading one stream to end before the other. Probe returns stdout; run returns stderr (unused except on failure).

Duration. ffprobe format duration; parse fail defaults to 5 seconds (would distort slide timing if probe fails).

3.10 VideoComposerService

ComposeSegment. Writes ffmpeg concat demuxer list: each slide file + duration = max(0.4, audioDuration / slideCount), last file repeated (ffmpeg concat still-image requirement). Mixes concat video with the MP3, scale/pad to configured size, fps, libx264 stillimage, aac, -shortest, faststart. -y overwrites.

Merge. Concat list of the eight MP4s. Tries stream copy first; on any exception re-encodes libx264+aac. That fallback is why mismatched timebases from vfr concat can still produce a playable master.

Path escaping for concat files: backslash → slash, single quote → ffmpeg concat escape.

3.11 DirectExecutor

File: Orchestration/DirectExecutor.cs (renamed from DirectPipelineRunner). Reference executor and failover path. Logs, prints status, rephrases only if NarrationPath is empty/missing (so the harness stub copy is not duplicated unless something deleted the file), then always segments, plans, renders, synthesizes, composes, merges. No skip-if-exists on media. Honors CancellationToken at the start and before segmentation. Return value is the merge tool’s string; ProductionApp reads MergedVideoPath from state after the harness returns.

3.12 AgentFactory and ProductionCrew

ProductionCrew is a record of seven AIAgent instances.

TryCreate. Builds one IChatClient: Azure OpenAI if endpoint set (key or DefaultAzureCredential), else OpenAI if OPENAI_API_KEY, else Ollama. Failure returns false → ProductionHarness uses DirectExecutor.

Each agent: chatClient.AsAIAgent(ChatClientAgentOptions) with id/name/description, instructions, tools, and two context providers. Then .AsBuilder().Use(guardrails.RunAsync).Use(guardrails.FunctionAsync).Build().

Instructions and handoff text interpolate SegmentCount, MaxSlidesPerSegment, and TargetTalkMinutes (plus StudioNaming audio/video ranges). Confirmed: prompts are no longer hardcoded to “8 scripts”.

File memory: MAF FileMemoryProvider + FileSystemAgentFileStore under output/agent-file-memory, working folder production-notes-{RunId}. That provider is constructed only inside TryCreate, so direct mode never starts it. Inferred: MAF may write extra files if agents use the file store during handoff/sequential.

Independently, PipelineStore writes run.txt, pipeline-status.txt, and notes.txt into the same timestamped folder on every persist, including direct mode. Older production-notes-* folders are kept. See also docs/memory-vs-mem0.pdf.

Chat client priority is Azure → OpenAI → Ollama. A developer with Azure env vars set will not use local Ollama for specialists even if Ollama is running. Confirmed in CreateChatClient.

3.13 WorkflowHost

Handoff. AgentWorkflowBuilder.CreateHandoffBuilderWith(coordinator). If stubbing, rewriter is omitted from the graph. Specialists hand back to coordinator. Coordinator has autonomous mode, turnLimit 8, continuation prompt to GetPipelineStatus. Inferred: MAF runtime interprets handoff conditions as natural-language routing hints to the model, not compiled predicates.

Sequential. BuildSequential with rewriter omitted when stubbing — because the harness already wrote the talk, not ProductionApp.

RunAsync. InProcessExecution.RunStreamingAsync, sends TurnToken(emitEvents: true), prints AgentResponseUpdateEvent text grouped by executor id, returns on WorkflowOutputEvent.

BuildUserPrompt. Injects stub vs Ollama rewrite step plus live SummarizeForAgent.

3.14 ProductionGuardrails

Inbound user messages containing blocked terms (harmful, illegal, violence, exploit, malware, bypass paywall) are replaced with a blocked marker; the run short-circuits with a refusal. All messages get email and ###-###-#### phone redaction.

FunctionAsync logs tool start/finish only. The previous “count the word slide and warn” path is gone. Script and slide caps are enforced in tools (throw) and again in HarnessChecks (fail the process). Guardrails apply only to agent runs, not DirectExecutor. Fuller write-up: docs/guardrails.pdf.

3.15 ProductionContextProvider

On invoke, injects instructions: current summary, exact file naming, segment/slide caps, stay on task. After invoke, appends truncated assistant text to PipelineState.Notes (max 24, drop oldest). Notes are persisted in pipeline-state.json and copied to the timestamped memory notes.txt. They are not injected back into ProvideAIContextAsync (audit log, not retrieval).

3.16 Configuration types

StudioOptions section Studio; OllamaOptions section Model. Defaults in the class match appsettings for segment counts, stubbing, voice id, video size. Options are captured at construction (IOptions<T>.Value), so reloadOnChange on JSON files does not update live option objects already injected. Confirmed: services store _options = options.Value.

4.2 Handoff orchestration

  1. Same init. Stub rewrite happens inside ProductionHarness before TryCreate.
  2. AgentFactory.TryCreate — if this returns false, jump to DirectExecutor.
  3. CreateHandoffWorkflow then RunAsync with user prompt and ApplicationStopping.
  4. Coordinator should call GetPipelineStatus and hand off. Specialists call tools that mutate store and disk (and append events.jsonl).
  5. Autonomous continuation up to 8 coordinator turns (inferred MAF semantics).
  6. If MergedVideoPath missing or file absent → warning log → DirectExecutor. Direct will not skip media generation, so a partial agent run is overwritten into a complete video (scripts already in memory if agents segmented; if not, direct segments from rewritten file).
  7. HarnessChecks.Verify always runs.

Subtlety. Direct after a partial agent run still requires in-memory Segments or it will call SegmentTranscriptIntoEightScripts from the rewritten file. Agent-authored scripts in memory are kept for that process; they are not reloaded from disk on a new process because Initialize wipes and does not hydrate from leftover JSON (JSON was also deleted).

4.3 Sequential orchestration

Same as handoff but BuildSequential runs specialists in a fixed list. Stubbing removes the rewriter from that list because the harness already wrote the talk.

Ollama client instance is cached for process lifetime. No artifact cache: reruns recompute everything. ImageSharp fonts are loaded per render call (minor cost).

9. Security

9.1 Authentication and authorization

No user login or roles. Anyone who can run the EXE as the current user can produce videos and read output/. The job API accepts unauthenticated requests when Service:ApiKey is empty (logs a warning). When set, clients send X-Api-Key. n8n Form Trigger is a public URL if the workflow is active — keep API keys on n8n credentials, not the form.

Outbound: ElevenLabs API key; optional OpenAI key; optional Azure key or DefaultAzureCredential (managed identity / VS / az cli — inferred Azure.Identity behavior).

9.2 Data protection

Transcripts and generated media sit unencrypted on disk under output/ (gitignored). Notes in pipeline-state.json may contain agent excerpts. PII redaction in guardrails is regex-only on agent messages, not on transcript files or TTS payloads. Emails in the source talk are sent to ElevenLabs in full. Confirmed: redaction does not wrap ProductionTools in direct mode.

9.3 Input validation

Filesystem paths are combined from config and args without a sandbox. A transcript argument of an unexpected file will be read if it exists. ffmpeg concat lists include absolute paths. There is no command-injection via ArgumentList (good: ProcessStartInfo.ArgumentList is used, not a single shell string).

9.4 Session / tokens

No app sessions. Named mutex is a lock, not auth. HttpClients do not implement retry/auth refresh.

10. Error Handling and Edge Cases

10.1 Propagation

Exceptions from services → tools → DirectExecutor or MAF tool invocation → ProductionHarness → ProductionApp catch logs Error and rethrows. After a “successful” tool loop, HarnessChecks can still throw. No global exception handler / EventId taxonomy beyond default logger categories.

10.2 Logging

ILogger on ProductionApp, ProductionHarness, DirectExecutor, AgentFactory, WorkflowHost, NarrationRewriteService, TtsService, ProductionGuardrails. Information for provider selection and ElevenLabs writes; Warning for stub rewrite, SAPI failure, agent create failure, incomplete agent merge, guardrail block; Error for pipeline failure and harness-check failure.

No structured file log, no Application Insights, no correlation ID beyond RunId in state/filenames.

10.3 Retries

OperationRetry
Delete generated filesUp to 8 attempts, backoff 150ms × attempt
PNG write6 attempts + sidecar copy
ffmpeg mergeOne fallback re-encode, not a counted retry
ElevenLabs / Ollama HTTPNone

10.4 Failure scenarios

  • Second instance: InvalidOperationException mutex.
  • Missing transcript / stub: FileNotFoundException.
  • Stub too short: InvalidOperationException.
  • Player has video_*.mp4 open: Initialize throws IOException after retries.
  • ffmpeg missing: Win32Exception / “failed to start ffmpeg”.
  • ElevenLabs 401/quota: InvalidOperationException with body; run aborts mid-audio (earlier MP3s already written this run; next run wipes them).
  • Ollama down in handoff: TryCreate may still construct a client; failure appears when the first model call happens. Direct mode with both stubs on never needs Ollama.
  • Agent never merges: failover DirectExecutor, then HarnessChecks.
  • Agent claims Done with missing files: HarnessCheckException; process exits non-zero.

10.5 Validation failures

Wrong agent JSON for SaveNarrationScripts, empty transcript, missing audio before compose. All throw; no partial merge if fewer than SegmentCount videos.

18.4 Key assumptions

  • One talk at a time; output directory is expendable.

18.5 Known limitations

  • No SPA, SQL, CI, or multi-run resume. Job API + n8n form are the HTTP surface. Unit tests cover checks/segmenter/planner/naming/job merge, not live media APIs.
  • Agent quality depends on the LLM; direct mode is the reliable factory; HarnessChecks is the Done gate.
  • Secrets currently live in appsettings.json.
  • No max transcript size; ElevenLabs character limits can fail a segment.
  • Slide on-screen text depends on Ollama unless UseStubSlidePhrases is true.
  • Slide timing is even split of audio duration, not word-level alignment.
  • Guardrails do not apply to direct mode. Caps are enforced in tools and HarnessChecks.

19. n8n job service

This section is how n8n is used with Narration Studio. Operator YAML and copy-paste compose commands live in docs/n8n-service.pdf (source docs/n8n-service.html / docs/n8n-service.md). The factory and n8n flowcharts are in §17.0 and docs/diagrams/.

19.1 Why n8n is outside the factory

n8n already runs in Docker on this PC (stack n8n-api_icountera, UI http://localhost:5678). The container cannot browse E:\…. Studio stays a Windows process so ffmpeg, SAPI, and Ollama on localhost:11434 keep working. n8n is the loop: each factory stage is a node. Studio is a sidecar that exposes one HTTP step per ProductionTools method. n8n does not write slides or audio.

POST /v1/sessions allocates output/jobs/{jobId}/ and returns 201 ready without enqueueing JobWorker. Each POST /v1/sessions/{id}/steps/{step} runs one tool. Mutex NarrationStudio.Production is taken except for render and tts, which may overlap. Short steps are synchronous 200. plan-slides and tts return 202 so n8n can Wait-poll steps[step]. Form values overlay appsettings.json defaults via JobOptionsMerger. Sessions force orchestration direct. POST /v1/jobs remains a compatibility run-all. API keys stay on n8n credentials, not the form.

19.2 How a form submission runs

  1. Operator opens the Form Trigger URL and uploads transcript + stub narration (browse). Other fields are pre-filled from appsettings.json.
  2. The custom node (n8n-nodes-narration-studio) POSTs JSON to http://host.docker.internal:5088/v1/sessions with real booleans/numbers and file text as transcriptText / stubNarrationText. Form binaries are often named Transcript_file / Stub_narration_file.
  3. Studio writes inputs, initializes pipeline-state.json, returns jobId with status: ready.
  4. Stage nodes POST /v1/sessions/{id}/steps/{step}. After plan-slides, render and TTS run in parallel. Wait For Step polls GET /v1/jobs/{id} steps[step] until that step is complete or failed.
  5. Verify runs HarnessChecks. Success is files on disk plus status == complete, not the coordinator’s last sentence. Then download /v1/jobs/{id}/artifacts/merged.
  6. Each step uses scoped DI and ProductionTools exactly as in the CLI. n8n sessions do not use MAF handoff.

19.3b Job API key

There is no generate-key endpoint. Mint a secret in PowerShell, e.g. [Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Maximum 256 }) -as [byte[]]), or a GUID. Put it in the bin appsettings.json Service:ApiKey, or set $env:Service__ApiKey and restart Studio. Until a key is set, the node may run with no credential. Full click-path: docs/n8n-service.pdf §3.1.

A Narration Studio API credential is one n8n vault record: Base URL http://host.docker.internal:5088 (not localhost inside Docker); API Key = the same string as Service:ApiKey, sent as X-Api-Key; optional ElevenLabs / OpenAI / Azure fields are other headers, not this key. Create it under Credentials → Add credential → search Narration Studio API (mounted node, not public npm). Test calls /health and only proves the URL is up.

Attach that credential on every Narration Studio node except the Form Trigger. If only Create session has it, later stage nodes get 401. Do not attach it to On form submission. The form is shareable; the job key is server-to-server (n8n encrypts the vault with N8N_ENCRYPTION_KEY). An ElevenLabs key in the API Key field will not unlock TTS and will 401 if it does not match Service:ApiKey. After rotating the Studio key, restart dotnet run and edit the credential.
